# Phase 3 実装・検証記録

実施日: 2026-09-19

## 実装

- `multifirm_host.h/.cpp` に固定レイアウト判定、3スロット走査、単一スロット検査、表示名決定、起動直前の再検証と起動処理を追加した。
- イメージ状態とメタデータ状態を分離した。メタデータの不在・破損・読み取り失敗・イメージ不一致は、検証済みアプリの `Ready` を変更しない。
- 表示名は、有効なメタデータ、有効な `project_name`、`AppN` の順で採用する。
- `MULTIFIRM_HOST` または `CONFIG_MULTIFIRM_HOST` のときだけホスト実装をコンパイルする。Kconfig の既定値は無効とした。
- UserDemo は `SlotInfo` を受け取る `AppOtaSlot` とスロット順の登録ループを使用する。従来の `AppApp1/2/3` は削除した。
- UserDemo は起動時と起動直前に確認画面を表示する。LVGL ロックは画面の生成・更新・破棄時だけ保持し、検証中は解放する。
- スロットごとの検証時間、SHA-256 計算時間、全スロット走査時間、起動直前検証時間をログへ出す。

## PC テスト

ネイティブ CTest 6件はすべて成功した。Python 生成 fixture を C++ 側でも使用し、次を確認した。

- メタデータのレコード、イメージ長、付加 SHA-256、ELF SHA、表示名、無効理由の一致
- メタデータあり、消去済み、CRC破損、イメージ長不一致、app digest不一致、ELF SHA不一致、ELF SHA省略
- `project_name` の通常値、既定値、不正UTF-8
- 空スロット、不正magic、後半破損、SHA不一致、各パーティション読み取り段階の失敗
- 個別スロットの読み取り失敗後も残りを走査すること、レイアウト異常時に走査結果を空にすること
- 走査後のイメージ変更を起動直前の再検証で拒否すること
- 起動先設定失敗時に shutdown と再起動を行わず、成功時だけ `verify → set → shutdown → restart` となること

## 実機

COM11 の ESP32-S3 rev 0.2、16 MiBフラッシュ、MultiFirm v1レイアウトで実施した。

- 更新前の `status --verify` で3スロットすべて `Ready`、表示名が `MultiFirm Arduino`、`MultiFirm IDF 5.5.0`、`MultiFirm IDF 5.5.4` であることを確認した。
- 16 MiBバックアップ `backup-28848543a7c0-20260919-163233.bin` を取得した。SHA-256は `5c5ea0862b28018fdec5f213759832c5ffd549893c75096d7e046e900b8c3f99` で、実機MD5と一致した。
- `install-host` で `ota_0` だけを更新した。読み戻しとイメージ検証に成功し、ブートローダ、表、メタデータ、3ゲスト、NVS、otadata、PHY、`multifirm_nvs` がバックアップと一致した。
- 初回実機起動で、空判定用の4 KiBローカル配列によるmainタスクのスタック不足を検出した。512 bytesずつ読む実装へ修正し、再ビルド・再更新後は安定して3スロットを走査した。
- 最終版の通常走査はスロット1/2/3が323/317/310 ms、うちSHA-256計算が129/123/119 ms、全体が990 msだった。
- スロット1へ別イメージ用の有効メタデータを一時配置すると `Ready`、`App1`、`image_size_mismatch` となった。magicを破損すると `Ready`、`App1`、`decode_error` となった。
- スロット3のイメージ後半を1 byte破損すると `Invalid` となり、メタデータ名を採用しなかった。
- 各異常試験後にバックアップの元セクタを復元した。最後の `status --verify` でホストと3スロットがすべて `Ready`、3つの表示名とdigestが更新前どおりであることを確認した。

端末上での手動操作が必要な次の項目は未確認である。

- ランチャー画面での3表示名と無効スロットの選択不可表示
- 各ゲストの起動、A+B、KEY.Bによる復帰、10往復
- 起動失敗画面を閉じてランチャーへ戻る操作、往復時の音・振動
- デバッガ接続中の破損検出

UserDemo のNVS修正、実ゲスト移行、旧ツール削除はPhase 3の対象外として変更していない。
